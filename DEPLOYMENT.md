# Deploying AtlasPad

AtlasPad has three deployable parts. Variable details are in [ENVIRONMENT.md](./ENVIRONMENT.md), and a copyable catalog is in [`.env.example`](./.env.example).

| Part | Path | What it is |
|---|---|---|
| Contracts | `contracts/` | Foundry project: `AtlasLaunchpad`, `AtlasGovernor`, `NationTreasury`, `NationToken`/`NationTokenFactory`. |
| Indexer | `apps/indexer` | Long-running Node process. Mirrors the chain into Postgres, runs the game engine, and serves `/health`, `/stream` (SSE) and `/admin/status`. |
| Web | `apps/web` | Next.js app. Reads Postgres server-side and talks to the chain through the user's wallet. |

Target: **Robinhood Chain mainnet**. It is an Arbitrum Orbit L2 with chain id `4663`, RPC `https://rpc.mainnet.chain.robinhood.com` and explorer `https://robinhoodchain.blockscout.com`.

## 1. Prerequisites

| Tool | Version | Notes |
|---|---|---|
| Node.js | `>=22.9` (from the root `package.json` `engines`) | The indexer's `dev`, `migrate` and `rebuild-game` scripts use `--env-file-if-exists`, which needs Node 22.9. The indexer bundle targets `node22`. |
| pnpm | 10 (`packageManager: pnpm@10.28.0`) | `corepack enable` picks the pinned version. |
| Foundry | `forge`, `cast`, `anvil` | `solc 0.8.28`, `evm_version = cancun` (see `contracts/foundry.toml`). |
| PostgreSQL | 16 | One database per network. The indexer refuses a database that was indexed for another chain id. |
| `psql`, `jq` | any | `psql` is used by `scripts/dev-local.sh`. `jq` is optional; it is used in the snippets below. |

For mainnet you also need a deployer account funded with ETH (for gas) on Robinhood Chain and some $WIF for the smoke test, plus the address that will receive protocol fees (preferably a multisig).

## 2. Install

```bash
git clone <repo> atlaspad && cd atlaspad
git submodule update --init --recursive   # contracts/lib/forge-std (v1.9.7), contracts/lib/openzeppelin-contracts (v5.6.1)
corepack enable
pnpm install
```

## 3. Contracts: build and test

```bash
pnpm contracts:build        # cd contracts && forge build
pnpm contracts:test         # cd contracts && forge test -vv   (fuzz runs: 512)
# Optional, deeper fuzzing using [profile.ci.fuzz] runs = 4096:
(cd contracts && FOUNDRY_PROFILE=ci forge test)
```

**`forge test` must pass before you deploy.** The contracts have no owner, no pause and no upgrade path, and every parameter is immutable. Fixing a mistake means a new deployment at new addresses and a fresh indexer database.

## 4. Deploy to Robinhood Chain mainnet

Run every `forge` command from `contracts/`.

### 4.1 Signer

`Deploy.s.sol` calls `vm.startBroadcast()` with no argument. The signer comes from forge CLI flags; **no environment variable holds the key**. The script header recommends an encrypted keystore:

```bash
cast wallet import deployer --interactive      # paste the key once; it is stored encrypted under ~/.foundry/keystores
cast wallet address --account deployer         # prints the deployer address
```

Hardware wallets work too: use `--ledger` or `--trezor`, plus `--sender <address>`. `--private-key` also works, but it leaks the key into shell history, so avoid it on mainnet.

### 4.2 Environment

Put these in `contracts/.env`, which Foundry auto-loads and git ignores, or export them in the shell. The `Deploy.s.sol` header points to the repository-root [`.env.example`](./.env.example) (section 4) for the full list:

```bash
ROBINHOOD_RPC_URL=https://rpc.mainnet.chain.robinhood.com   # or your provider's URL; foundry.toml alias "robinhood"
BLOCKSCOUT_API_KEY=                                         # must be defined for --verify on chain 4663; empty is accepted
EXPECTED_CHAIN_ID=4663
UNISWAP_V2_FACTORY=0x8bceaa40b9acdfaedf85adf4ff01f5ad6517937f
UNISWAP_V2_ROUTER=0x89e5db8b5aa49aa85ac63f691524311aeb649eba
WIF_ADDRESS=0x5173b8eA6923c2d40267890D45C46a3480954773     # $WIF; must equal WIF_ADDRESS in packages/shared/src/chains.ts
PROTOCOL_FEE_RECIPIENT=<your multisig>                      # immutable
GRADUATION_WIF=<$WIF base units, 1e6–1e36>                 # immutable; recommended 200000000000000000000000 (200,000 WIF)
CREATION_FEE_WIF=<$WIF base units, 0–GRADUATION_WIF>        # immutable, burned per founding; recommended 100000000000000000000 (100 WIF)
```

**Where the DEX values come from.** The Uniswap and $WIF addresses come from `packages/shared/src/chains.ts` (`ROBINHOOD_DEX`, `WIF_ADDRESS`) and the `Deploy.s.sol` header. They **must** match `chains.ts`, because on `robinhood` the web app and the indexer ignore `*_UNISWAP_V2_*` / `*_WETH` / `*_WIF` and always use those constants. If $WIF does not have 18 decimals (the preflight logs them), set `WIF_DECIMALS` in `chains.ts` too.

**Effect on local runs.** Foundry also loads `contracts/.env` for `DeployLocal.s.sol`, but that script reads only `LOCAL_GRADUATION_WIF` (default 200,000 WIF) and `LOCAL_CREATION_FEE_WIF` (default 100 WIF), never `GRADUATION_WIF` / `CREATION_FEE_WIF`. Production values in `contracts/.env` therefore do not leak into local seeding or the integration test.

### 4.3 Optional dry run (simulation only)

```bash
forge script script/Deploy.s.sol --rpc-url robinhood --sender <DEPLOYER_ADDRESS>
```

This runs the preflight against the live chain and simulates the deployment without sending anything.

A dry run does **not** write `contracts/deployments/4663.json`. The script detects that it is not broadcasting (`vm.isContext` is neither `ScriptBroadcast` nor `ScriptResume`), writes the predicted addresses to `contracts/deployments/4663.dry-run.json` (gitignored) and logs `DRY RUN (nothing deployed); predicted addresses at …`. Do not configure anything from the dry-run file.

### 4.4 Broadcast and verify

This is the exact command from the `Deploy.s.sol` header:

```bash
forge script script/Deploy.s.sol --rpc-url robinhood --account deployer --broadcast --verify \
  --verifier blockscout --verifier-url https://robinhoodchain.blockscout.com/api/
```

Do not send other transactions from the deployer account while this runs. The script predicts the treasury, governor and launchpad addresses from consecutive nonces, and asserts that the deployed addresses match.

The console must show all of the following:
- `Preflight OK on chain 4663`
- `Postflight OK`
- `Deployment recorded at …/contracts/deployments/4663.json`
- The three addresses

**If source verification fails or times out**, retry it per contract:

```bash
forge verify-contract <ADDRESS> src/AtlasLaunchpad.sol:AtlasLaunchpad --chain 4663 \
  --verifier blockscout --verifier-url https://robinhoodchain.blockscout.com/api/ \
  --rpc-url robinhood --guess-constructor-args
```

Use the same command for `src/AtlasGovernor.sol:AtlasGovernor` and `src/NationTreasury.sol:NationTreasury`. Also verify `src/NationTokenFactory.sol:NationTokenFactory` at `.tokenFactory`; the launchpad constructor creates it.

### 4.5 What the script checks

**Preflight** runs before any gas is spent. It requires:
- `block.chainid == EXPECTED_CHAIN_ID`.
- The factory, router and $WIF all have code; $WIF's symbol, decimals and supply are logged (check them).
- `router.factory() == UNISWAP_V2_FACTORY`.
- `factory.getPair()` is callable.
- `PROTOCOL_FEE_RECIPIENT != 0`.
- `1e6 ≤ GRADUATION_WIF ≤ 1e36`.
- `CREATION_FEE_WIF ≤ GRADUATION_WIF`.

**Deployment.** The contracts are deployed in this order: `NationTreasury`, `AtlasGovernor`, `AtlasLaunchpad`, wired together through the predicted addresses. The script then requires every deployed address to equal its prediction.

**Postflight** checks the full wiring:
- The launchpad's factory, $WIF (and the treasury's $WIF), treasury, governor, fee recipient, graduation and creation fee.
- `tokenFactory().launchpad()`.
- The treasury↔governor↔launchpad back-references.
- `nationCount() == 0`.

### 4.6 Deployment record

A broadcast run writes `contracts/deployments/<chainId>.json`, so `contracts/deployments/4663.json` on mainnet (a dry run writes only `4663.dry-run.json`, see 4.3). It contains these fields:
- `chainId`, `deployedAtBlock`, `deployedAtTimestamp`, `deployer`
- `launchpad`, `governor`, `treasury`, `tokenFactory`
- `uniswapV2Factory`, `uniswapV2Router`, `weth`
- `protocolFeeRecipient`, `graduationWifWei`, `creationFeeWif`

Forge also writes the transaction log to `contracts/broadcast/Deploy.s.sol/4663/run-latest.json`. Neither path is gitignored (only the 31337 and dry-run artifacts are), so **commit both** after a successful deployment.

### 4.7 Choosing the deploy block

The record's `deployedAtBlock` is the `block.number` forge saw **before** broadcasting. The contracts land a few blocks later (locally the record says `0` while the transactions landed in blocks 1–4), which makes it a lower bound for `ATLAS_DEPLOY_BLOCK` there: starting a little early only means scanning a few extra blocks. One caveat: on an Arbitrum Orbit chain the EVM's `block.number` can follow the parent chain rather than the L2 block number, depending on how your Foundry version treats the chain. So check the value against the real receipts:

```bash
jq -r '.receipts[].blockNumber' contracts/broadcast/Deploy.s.sol/4663/run-latest.json | xargs -n1 cast to-dec | sort -n | head -1
```

Use the recorded `deployedAtBlock` if it is ≤ that number; otherwise use that number, or the explorer's creation block of the `NationTreasury` (the first contract deployed), as `ATLAS_DEPLOY_BLOCK` / `NEXT_PUBLIC_ATLAS_DEPLOY_BLOCK` (digits only). Any value ≤ the first deployment block is safe, because the indexer starts at `ATLAS_DEPLOY_BLOCK - 1`. A value that is too high silently skips events, and it cannot be changed later without resetting the database.

To print the address variables:

```bash
jq -r '"ATLAS_LAUNCHPAD=\(.launchpad)\nATLAS_GOVERNOR=\(.governor)\nATLAS_TREASURY=\(.treasury)"' contracts/deployments/4663.json
```

Add the `NEXT_PUBLIC_` prefix for the web app.

### 4.8 Verify the deployment (read-only)

```bash
forge script script/VerifyDeployment.s.sol --rpc-url robinhood
```

This reads `deployments/<chainid>.json` and checks the following against the live chain:
- Each of the three contracts has code.
- The launchpad's and treasury's factory and $WIF, and the router's `factory()`.
- All cross-references, the fee recipient and the token factory.
- Treasury solvency: `balance >= totalHeld()`.
- Launchpad solvency: `balance >= Σ realWif + protocolFeesAccrued`.

The solvency checks use `>=`, so $WIF transferred straight to a contract cannot make verification fail. It prints the nation count, proposal count, treasury $WIF held, $WIF burned and $WIF locked in pools. You can re-run it at any time.

### 4.9 Smoke test (spends real $WIF and creates a permanent nation)

Run this after the indexer and web are configured (sections 6–7), so you can watch the nation appear.

```bash
SMOKE_NAME="Atlas Test" SMOKE_SYMBOL=ATEST SMOKE_CONFIRM=I_UNDERSTAND \
forge script script/SmokeTest.s.sol --rpc-url robinhood --account deployer --broadcast
```

**Guard.** On any chain other than 31337 the script reverts unless `SMOKE_CONFIRM=I_UNDERSTAND`.

**What it does.** It reads `.launchpad` from `deployments/<chainid>.json`, then:
1. Founds a nation (supply 1e9 tokens, founder allocation 0, theme 6), approving and spending `creationFee` (burned) + `SMOKE_INITIAL_BUY_WIF` (default **100 WIF**).
2. Buys again with `SMOKE_BUY_WIF` (default **200 WIF**).
3. Sells half its balance back.

It then asserts the founder, the balance and the voting power, and logs the nation id, the token, the $WIF spent and returned, the curve reserve and the $WIF burned. The cost is the creation fee + about 300 WIF + gas, minus what the sell returns. Both trades use `minOut = 0`, which is acceptable only at these tiny sizes.

**Permanence.** Names (case-insensitive) and tickers are unique forever. The smoke nation is a real, public nation, and a second run with the same name reverts with `NameTaken`. A name is 2–32 characters from `[A-Za-z0-9 -.']`; a ticker is 2–10 characters from `[A-Z0-9]`.

## 6. Database and indexer

### 6.1 Database and migrations

Create an empty PostgreSQL 16 database for mainnet. The schema lives in `packages/db/src/schema.ts`, and the migrations in `packages/db/drizzle/`. There are three ways to apply them, all idempotent and all using the Drizzle migrator:
- **Indexer startup (default).** The indexer applies migrations when it starts, unless `INDEXER_RUN_MIGRATIONS=false`. The indexer role then needs DDL rights. In a build, it uses the copy in `dist/drizzle` (or `MIGRATIONS_DIR`).
- **Indexer migrate command.** From a build, `node apps/indexer/dist/migrate-cli.js` (with `DATABASE_URL` and optionally `DATABASE_SSL=true` exported; it loads no `.env` file) applies the migrations from `dist/drizzle` (or `MIGRATIONS_DIR`), prints `Migrations applied` and exits. From source, `pnpm --filter @atlaspad/indexer migrate` does the same and loads `apps/indexer/.env.local`, then the repo-root `.env`.
- **Workspace script.** `DATABASE_URL=… [DATABASE_SSL=true] pnpm db:migrate`. It loads no `.env` file, so export the variables.

The last two work with `INDEXER_RUN_MIGRATIONS=false` when you run migrations with a separate owner role.

After changing `schema.ts`, generate a new migration with `pnpm db:generate` (drizzle-kit) and commit it.

### 6.2 Build and run

```bash
pnpm --filter @atlaspad/indexer build     # tsup (target node22) → dist/main.js, dist/rebuild.js, dist/migrate-cli.js (+ chunks); copies packages/db/drizzle → dist/drizzle
pnpm --filter @atlaspad/indexer start     # node dist/main.js  (no .env file is loaded: set process env)
```

**Runtime dependencies.** Workspace packages are bundled, but npm dependencies (`viem`, `postgres`, `drizzle-orm`) stay external. Run the indexer from an installed checkout.

**Minimum production environment:**

```bash
ATLAS_NETWORK=robinhood
ATLAS_RPC_URL=<dedicated provider URL>
ATLAS_LAUNCHPAD / ATLAS_GOVERNOR / ATLAS_TREASURY   # from contracts/deployments/4663.json (all three, or the indexer exits)
ATLAS_DEPLOY_BLOCK                                   # see 4.7 (digits only)
DATABASE_URL
INDEXER_CORS_ORIGIN=https://<your web origin>
INDEXER_ADMIN_TOKEN                                  # optional
```

Empty values count as unset. A configuration error (an unknown network, an invalid address, only one or two of the three addresses, a non-digit deploy block, an unknown `WIF_USD_SOURCE`) makes the indexer exit at startup.

The optional variables are `WIF_USD_SOURCE=dexscreener`, `EXCLUDED_ADDRESSES`, `INDEXER_CONFIRMATIONS`, `INDEXER_BATCH_BLOCKS`, `INDEXER_POLL_MS`, `LOG_LEVEL`, `PORT`/`INDEXER_PORT` (default 4100) and `DATABASE_SSL`.

**Endpoints:**
- `GET /health` (public). Returns `chainId`, `deployed`, `lastIndexedBlock`, `chainHeadBlock`, `lagBlocks`, `lastSyncAt` and `subscribers`.
- `GET /stream` (public SSE). At most 5000 clients per process, with a heartbeat every 15 s (one shared timer and one database query for all clients, published only while someone is subscribed).
- `GET /admin/status` (Bearer `INDEXER_ADMIN_TOKEN`; 404 when no token is set). The RPC URL is shown as `protocol//host`, plus `/***` when it has a path, query or credentials.

**Run exactly one indexer per database.** Progress is a single cursor row (`indexer_state.id = 'main'`) with no locking.

**First start.** On first start the indexer:
1. Checks that the RPC chain id is 4663 and that the database was not indexed for another chain.
2. Seeds `excluded_addresses`.
3. Backfills from `ATLAS_DEPLOY_BLOCK - 1`.

### 6.3 Rebuild game state

Game state is a deterministic replay of the on-chain mirror. To recompute it, for example after a game-rule change, stop the indexer and run:

```bash
pnpm --filter @atlaspad/indexer rebuild-game   # tsx; loads apps/indexer/.env.local, then the repo-root .env (like dev)
# or, from a build:
node apps/indexer/dist/rebuild.js              # with the indexer's environment exported
```

The rebuild resets `indexer_state.game_cursor` to 0 and replays up to the last indexed block.

## 7. Web

```bash
# NEXT_PUBLIC_* must be present at build time (they are inlined).
pnpm --filter @atlaspad/web build    # next build
pnpm --filter @atlaspad/web start    # next start (port 3000 by default; `next start -p <port>` to change)
```

`pnpm build` at the root builds the web app and the indexer together. `NEXT_PUBLIC_*` must be set for that too.

**Build-time variables:**
- `NEXT_PUBLIC_ATLAS_NETWORK=robinhood`
- `NEXT_PUBLIC_ATLAS_LAUNCHPAD`, `NEXT_PUBLIC_ATLAS_GOVERNOR`, `NEXT_PUBLIC_ATLAS_TREASURY` (all three; setting only one or two is a configuration error that shows a banner and disables on-chain actions)
- `NEXT_PUBLIC_ATLAS_DEPLOY_BLOCK` (digits only)
- `NEXT_PUBLIC_REALTIME_URL`
- `NEXT_PUBLIC_SITE_URL` (your public origin, for example `https://your-domain.example`; when unset or empty it defaults to `http://localhost:3000`)
- `NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID` (optional)
- `NEXT_PUBLIC_RPC_URL` (optional; it must be a public URL)

Empty values count as unset.

**Runtime (server) variables:**
- `DATABASE_URL` (plus `DATABASE_SSL` and `DATABASE_POOL_MAX`, which must be a positive integer; default 3)
- `ADMIN_USERNAME` and `ADMIN_PASSWORD` (the password must be at least 12 characters; a shorter one logs a warning once and keeps the admin area disabled)
- `INDEXER_URL` and `INDEXER_ADMIN_TOKEN`, used by the admin dashboard
- `ATLAS_RPC_URL` (optional; used by admin status)

> ⚠ `scripts/dev-local.sh` writes `apps/web/.env.local` with **anvil** settings, and Next.js loads `.env.local` in production builds too. Before a production `next build` on the same machine, delete that file, or override every value in the shell or in `apps/web/.env.production.local`, which takes precedence over `.env.local`.

## 8. Hosting notes

**Web**
- It needs a Node server (`next start`). The API routes are dynamic and query Postgres, so a static export does not work.
- `DATABASE_URL` is server-only. The web app only reads, so a read-only role is enough.
- `DATABASE_POOL_MAX` applies per server instance. Keep it small on serverless or autoscaled hosts. Transaction-mode poolers are supported (`prepare: false`).

**Indexer and realtime**
- `NEXT_PUBLIC_REALTIME_URL` must be reachable **from users' browsers**. Use HTTPS when the site is served over HTTPS, to avoid mixed content.
- Proxies in front of `/stream` must not buffer SSE. The indexer sends `X-Accel-Buffering: no` for nginx and a heartbeat every 15 s.
- Without a realtime URL the UI still works by polling.
- `INDEXER_CORS_ORIGIN` must be the web origin exactly (scheme + host + port) or `*`. It is a single value, sent on every indexer response including the SSE stream.
- Expose only `/health` and `/stream` publicly. `INDEXER_URL`, used by the web admin page, can be a private address.
- With `PORT` set in the environment (common on PaaS), the indexer listens on `PORT` instead of `INDEXER_PORT`. `next start` also honours `PORT`, so give each service its own environment.

**Admin**
- The `/admin` dashboard is read-only and HTTP Basic protected, so serve it only over HTTPS.

## 10. Local end-to-end (anvil)

This is for local development only. Nothing here touches a public network.

**Requirements:**
- Foundry (`anvil`, `cast`, `forge`) and `psql`.
- A local Postgres. For example, as a superuser:
  ```bash
  psql -c "CREATE ROLE atlas LOGIN PASSWORD 'atlas' CREATEDB;"
  createdb -O atlas atlaspad
  ```
- Run `pnpm contracts:build` once while online. The local deploy uses `forge script … --offline`, so `solc 0.8.28` must already be installed.

### 10.1 `scripts/dev-local.sh` (`pnpm dev:local`)

```bash
DATABASE_URL=postgresql://atlas:atlas@localhost:5432/atlaspad ./scripts/dev-local.sh
```

The script runs these steps:

1. **anvil.** If nothing answers on `127.0.0.1:8545`, it starts `anvil --port 8545` with its clock set to 7 days ago. An already-running anvil is reused.
2. **Database reset.** It **resets the database** at `DATABASE_URL` (default `postgresql://atlas:atlas@localhost:5432/atlaspad`) with `DROP SCHEMA public CASCADE; CREATE SCHEMA public; DROP SCHEMA drizzle CASCADE`. **Never point it at a real database.**
3. **Deploy and seed.** It runs `apps/indexer/scripts/seed-local.ts`, which:
   - refuses any chain except 31337;
   - deploys WETH9, Uniswap V2 ports and AtlasPad with `forge script script/DeployLocal.s.sol` (anvil key #0), which writes `contracts/deployments/31337.json`;
   - runs the scripted scenario from `apps/indexer/test/scenario.ts` (real transactions: founding, trades, graduation, governance);
   - founds eight more nations with trades, advances time, and moves the chain clock up to wall time;
   - **overwrites** `apps/indexer/.env.local` (`ATLAS_NETWORK=local`, addresses, `INDEXER_CONFIRMATIONS=0`, `INDEXER_CORS_ORIGIN=*`, `DATABASE_URL`);
   - **overwrites** `apps/web/.env.local` (`NEXT_PUBLIC_*` local config, `NEXT_PUBLIC_RPC_URL`, `NEXT_PUBLIC_REALTIME_URL=http://127.0.0.1:4100`, `DATABASE_URL`).
4. **Indexer.** It starts the indexer with `npx tsx --env-file=.env.local src/main.ts`. Migrations run on startup, and health is at `http://localhost:4100/health`.
5. **Web.** It starts the web app with `npx next dev --port 3000` at `http://localhost:3000`.

The processes are detached (`setsid nohup`) and the script returns immediately. Logs go to `$LOGS_DIR` (default `/tmp/atlaspad-dev`): `anvil.log`, `indexer.log` and `web.log`. Stop them before re-running:

```bash
pkill -f "anvil --silent --port 8545"; pkill -f "src/main.ts"; pkill -f "next dev --port 3000"
```

`pnpm --filter @atlaspad/indexer seed:local` runs only the deploy-and-seed step. It uses `LOCAL_RPC_URL`, default `http://127.0.0.1:8545`.

### 10.2 Browser E2E (`pnpm e2e`)

With the dev-local stack running:

```bash
pnpm e2e                                                     # = node apps/web/e2e/flows.e2e.mjs (base URL http://localhost:3000)
node apps/web/e2e/flows.e2e.mjs [baseUrl] [screenshotDir]    # defaults: http://localhost:3000, apps/web/e2e/screenshots (gitignored)
CHROMIUM_PATH=/path/to/chrome node apps/web/e2e/flows.e2e.mjs
```

**Browser.** The script drives Chromium through `playwright-core` (no bundled browser). `CHROMIUM_PATH` defaults to `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`.

**Wallet.** It injects a test EIP-6963 wallet (`apps/web/e2e/wallet.js`) bound to anvil account #9 (`0xa0Ee…9720`). That wallet forwards signing to the unlocked anvil node at `http://127.0.0.1:8545`. Like a real wallet, it exposes no account until the page connects, and it remembers the approval in `localStorage`, so the connection survives page reloads.

**Flow.** It runs these 12 steps in order:
1. Open the founding wizard.
2. Connect the wallet (EIP-6963).
3. Check name and ticker availability.
4. Fill in the description, theme and symbol.
5. Set the token parameters, with the live curve preview.
6. Simulate, acknowledge and found a new nation, named `Testopia XXXX` / `TXXXX`, so each run creates a new one.
7. Open the nation once the indexer has picked it up.
8. Buy on the bonding curve.
9. Sell 50% with a permit signature.
10. Propose a Capitol through governance.
11. Check that the proposal appears through the indexer.
12. Check that the new nation appears on the world map.

**Results.** Each step prints ✓ or ✗. On failure the script saves `FAILED-<step>.png` and exits with code 1.

### 10.3 Indexer integration tests

```bash
INTEGRATION=1 TEST_DATABASE_URL=postgresql://atlas:atlas@localhost:5432/atlaspad_test \
  pnpm --filter @atlaspad/indexer test
```

This runs real contracts on anvil → indexer → Postgres → game engine. Without `INTEGRATION=1` the suite is skipped.

**Prerequisites** (from `apps/indexer/test/integration.test.ts` and `vitest.config.ts`):
- `anvil` and `forge` on `PATH`. The test spawns its own anvil on **port 8547**, which must be free, with `--timestamp 1790000000`.
- Solc 0.8.28 already installed. The test deploys through `forge script script/DeployLocal.s.sol --offline`, which also rewrites `contracts/deployments/31337.json`.
- A Postgres server the `TEST_DATABASE_URL` role can use, and the role must be able to:
  - connect to the `postgres` maintenance database on the same server;
  - run `DROP DATABASE … WITH (FORCE)` and `CREATE DATABASE`, so it needs `CREATEDB` and ownership of the test DB.
- The test database (default `atlaspad_test`) is **dropped and recreated** on every run. Use a plain URL with no query string.
- Timeouts: hooks 300 s, tests 60 s. Files run sequentially.

**What it checks** (7 tests):
- Nations, curve state and graduation.
- Holder balances against the chain.
- Curve and Uniswap trades.
- Governance and game decrees.
- News generation.
- Deterministic game replay. Set `DIGEST_DIR` to dump `before.json` / `after.json` when the replay differs.
- That the shared rule constants in `packages/shared` match the deployed contracts ("shared rule constants match the deployed contracts").
